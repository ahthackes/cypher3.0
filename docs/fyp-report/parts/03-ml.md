# Part 3 — ML engine

## Files covered

`src/cypher/detect/ml/isolation_forest.py`,
`src/cypher/detect/ml/autoencoder.py`,
`src/cypher/detect/ml/registry.py`, `src/cypher/detect/ml/trainer.py`,
`src/cypher/detect/ml/onnx_runtime.py`

## Purpose

Implements FR-3 (local training on historical data) and the "AI layer"
from the original proposal. See `docs/ml-evaluation.md` for the full
reasoning behind the choices here and the evaluation methodology —
this part covers how the code works, that document covers why these
specific models and the plan for proving they're good enough.

## How it works

**`isolation_forest.py`'s `IsolationForestScorer`** wraps
scikit-learn's `IsolationForest`. `fit(X)` requires at least 10 samples
(an explicit guard rather than a cryptic sklearn error). `score(x)`
converts sklearn's `decision_function` output — which is *higher* for
normal points and often negative for anomalies — into the project's
0-100 convention via `(0.5 - raw) * 100`, clipped to the valid range.
`save()`/`load()` use `joblib` for serialization.

**`autoencoder.py`'s `ReconstructionScorer`** is a PCA-based stand-in
for a full neural autoencoder (see `ml-evaluation.md` for why). It fits
a PCA projection on normal training data, then measures each new
point's reconstruction error (how much information is lost projecting
it down to `n_components` and back). The error is rescaled against the
99th-percentile training error rather than the raw maximum, so a single
extreme outlier in the training set can't compress the whole score
range. Same `fit`/`score`/`save`/`load` interface as the Isolation
Forest scorer, deliberately — swapping in a real Keras/PyTorch model
later means changing only this one file.

**`registry.py`'s `ModelRegistry`** tracks every trained model version
as a JSON file (`registry.json`) alongside the `.joblib` files
themselves — each entry records name, version number, training
timestamp, sample count, and the backing file name. `register()`
auto-increments the version per model name. This is what lets the
dashboard show "model trained on \<date\>, N samples" (FR via
`api/routes/models.py`) and lets `cypher train` never silently
overwrite a previous model — every training run produces a new
versioned file.

**`trainer.py`'s `train_from_events()`** is the glue: takes a list of
historical `Event` objects, runs them through the same
`FeatureVectorizer` the live pipeline uses (so train-time and
inference-time features are guaranteed identical), fits the Isolation
Forest (always) and the reconstruction model (only if
`ml.autoencoder_enabled`), and registers both via `ModelRegistry`.
Requires at least 20 events, with a message pointing at
`scripts/generate_normal_traffic.py` if that's not met yet. Training
never touches the live pipeline directly — a newly trained model is
only picked up on the next process restart or scheduled reload
(`ml.retrain_interval_hours`), so a bad training run can be reviewed
before it goes live.

**`onnx_runtime.py`** is an optional, explicitly-not-required-for-NFR-1
export/inference path — see its own docstring for when you'd actually
want it (a smaller deploy footprint without a full scikit-learn
install). Guarded behind the `ml` extra (`pip install -e ".[ml]"`) so
the core install stays lean.

## Security / reliability considerations

- Training happens offline, from locally-stored historical events —
  satisfies NFR-3 (100% offline) directly; there is no code path in
  this module that makes a network call.
- A corrupted or adversarially-crafted training set (e.g. if an
  attacker could inject log lines designed to make the model learn
  their attack pattern as "normal") is a real, acknowledged limitation
  of any unsupervised anomaly detector trained on live data — mitigated
  in practice by training on a period of known-clean traffic and only
  retraining on a fixed schedule, not continuously, so one bad day
  can't quietly poison the model.

## Testing

`tests/integration/test_pipeline_replay.py::test_isolation_forest_flags_outlier_after_training`
fits on synthetic normal data and confirms an obvious outlier scores
higher than a normal point — a deliberately simple, interpretable test
rather than asserting an exact score. The CLI smoke tests
(`cypher train` run against replayed demo data, see
`parts/06-testing.md`) confirm the full train → register → save →
reload path works end to end, including the `cypher status` and
dashboard paths reading the trained model back correctly. A fuller
precision/recall evaluation against labeled data is planned per
`docs/ml-evaluation.md`, not yet run (needs the VM lab).
